# Auto Icon

根据笔记内容，自动在**笔记开头**配一个图标。32 个内置类别，本地规则引擎默认离线可用，AI 分类可选。

图标写在正文第一行（不是 frontmatter），用的是本地打包的 [IconPark](https://github.com//iconpark/iconpark) 图标集（Apache-2.0），2658 个图标 + 4 种样式，全部离线可用。

---

## 一句话激活

安装启用后提示一句：

> **Auto Icon 已就绪 —— 运行命令「为当前笔记添加图标」，图标会出现在笔记开头。**

---

## 图标放在哪里

写在**正文第一行**，一行一个自描述的 SVG：

```html
<svg class="auto-icon" data-icon="folder" data-theme="outline" width="20" …><path …/></svg>

# 项目说明
```

**为什么不用 frontmatter。** 第一版写的是 frontmatter 的 `icon:` 字段。它确实是「零侵入」的，但正因为它藏在元数据里，你得打开属性面板才看得见，而笔记本身看起来跟别的笔记毫无区别——这就不对了。图标应该在打开笔记的第一眼就出现。

这样做有三个好处：

- **看得见**：Obsidian 阅读视图会渲染内联 HTML，编辑视图由插件的样式负责。
- **可逆**：`data-icon` / `data-theme` 自带身份，重跑是**替换**而不是追加，识别时不需要重新解析路径数据。
- **不破坏正文**：这一行之外的内容一个字节都不动。

后面那个空行是必须的——它把 HTML 块和下面的 Markdown 隔开，否则标题会被吞进 HTML 块里。

## 图标来源：IconPark，本地打包

**为什么是 IconPark。** 你的需求里有「可以选择图标样式」。IconPark 的 4 种样式（线性 / 填充 / 双色 / 多彩）不是四套不同图形，而是**同一套图形的四种上色方案**——所以样式几乎不占体积，4 种全部随包发布，不存在「选了样式要另外下载」。Lucide 没有原生的样式变体。

| | 图标数 | 样式 | 许可 |
|---|---|---|---|
| **IconPark** | 2658 | **4 种**（线性/填充/双色/多彩） | Apache-2.0 |
| Lucide | 1877 | 无原生变体 | ISC |

### 为什么不塞进 main.js

完整图标集约 1.2 MB。塞进 `main.js` 意味着 Obsidian 每次加载插件都要解析这 1.2 MB。所以它是一个**独立文件** `icons/iconpark.json`：

- `main.js` 只有 **60 KB**，加载是瞬时的
- 图标集**第一次用到时才读一次**，读完缓存在内存
- 全程离线，不请求任何网络

生成脚本：`npm run icons`（读 `node_modules/@icon-park/svg`，版本被 package-lock 钉死，可复现）。

### 样式是免费的

生成时用哨兵色 `C0..C3` 渲染每个图标，把哨兵保留在存下来的 markup 里；显示时再把真颜色替换进去。所以**一个存储的图标服务全部 4 种样式**。

> 生成时必须用 `multi-color` 主题：只有它会把 `fill` 数组原样映射到四个色槽。`outline` 会把 `none` 同时放进槽 1 和槽 3，存下来的 markup 会有歧义。

另外 `stroke-width` / `stroke-linecap` / `stroke-linejoin` 在每个图标的每条路径上重复出现，已从路径剥离、提到根 `<svg>` 上（这些属性可继承），全量省下约 400 KB。

### 不想手工输入

上一版让你手打 `lucide:folder-kanban`——那是个等着出错的输入，而且在提交之前看不到图标长什么样。现在：

- **换图标**：点「换图标」→ 弹出可搜索的网格，**渲染出来的真实图标**，还能当场切样式
- **样式**：设置里一个下拉框，线性/填充/双色/多彩
- **强调色**：双色和多彩样式下的副色，可调

设置里唯一能输入文本的地方，是文件夹路径、类别显示名和关键词——这些确实没有固定词表。

## 32 个类别

上限是硬性的，在 `assertCategoryLimit` 里强制，不靠约定。

每个类别都能改名、换图标、改关键词、删除，也能自己加。设置里**内置类别和自定义类别分成两块显示**——自定义类别看起来就该和内置的固定词表区分开，不然一个自定义类别看起来就像内置表里的一个笔误。

### 显式声明优先

frontmatter 里写 `type:` / `category:` / `kind:` 直接指定，权重 100，压过一切推断。

---

## 匹配是怎么算分的

七路信号加权，**每路每类别最多算一次命中**——否则一篇长文顺带提到 `bug issue error defect 故障 异常`，就能靠篇幅压过一条用户明确写的 `#task` 标签。

| 信号 | 权重 |
|---|---|
| frontmatter 声明 | 100 |
| 标签精确命中 | 10 |
| 文件夹 | 6 |
| 标签关键词 | 5 |
| 文件名 | 4 |
| 小标题 | 3 |
| 正文 | 1 |

**默认最低分 4**，卡在文件夹和正文之间：明确的标签或文件夹会配图标，正文里偶然一词不会。这就是「有用」和「每篇笔记挂个随机符号」的分界线。

中文没有词边界，所以关键词是**子串匹配**。每个判定都给出理由，预览窗口直接显示。

## 安全

- **预览**：写入前弹窗，逐文件列出真实渲染的图标 + 判定依据
- **不覆盖**：默认只给没有图标的笔记配，手动改过的不会被自动替换
- **不乱删**：分类失败的笔记**不会被清空图标**，只是不写。匹配不上和该删是两回事
- **范围可控**：设置里指定文件夹，留空 = 整个 vault
- **换样式是独立动作**：命令「把全库图标换成当前样式」只改外观，不重新分类

---

## 命令

| 命令 | 作用 |
|---|---|
| 为当前笔记添加图标 | 单篇 |
| 扫描整个 vault 并添加图标 | 按设置范围 |
| 扫描当前文件夹并添加图标 | 当前笔记所在文件夹 |
| 把全库图标换成当前样式 | 只换外观 |
| 清除当前笔记的图标 | 移除开头那行 |

## 安装

```bash
cd code/obsidian-auto-icon
npm install
npm run build
```

产物是 `main.js` + `manifest.json` + `styles.css` + `icons/iconpark.json`。**四个文件都要。**

```bash
OUTDIR="/path/to/your/vault/.obsidian/plugins/auto-icon" npm run build
```

## 开发

```bash
npm run icons       # 重新生成 icons/iconpark.json
npm run typecheck
npm test            # 135 个测试
npm run smoke       # 构建并真实加载 main.js + 读图标集
npm run dev
```

### 代码结构

| 文件 | 职责 |
|---|---|
| `src/placement.ts` | 图标行在正文开头的插入/替换/移除（纯函数） |
| `src/iconset.ts` | 图标集加载（懒加载 + 并发去重）、样式上色 |
| `src/categories.ts` | 32 个默认类别、关键词、32 上限强制 |
| `src/classifier.ts` | 信号提取 + 本地规则打分（纯函数） |
| `src/ai.ts` | 可选 AI 分类器，实现同一个接口 |
| `src/planner.ts` | 生成可预览的改动计划 |
| `src/main.ts` | 命令、扫描流程、frontmatter 切分 |
| `scripts/build-iconpark.mjs` | 生成图标集 |
| `scripts/smoke.js` | 冒烟加载产物 |

分类和放置逻辑都是不依赖 Obsidian 的纯函数，所以可以脱离 vault 单测——风险本来就在这里。

### 测试

```
tests/
├── placement.test.ts   # 插入/替换/幂等/CRLF/代码块保护/逐字节还原
├── iconset.test.ts     # 读真实生成的 iconpark.json
├── categories.test.ts  # 32 个类别 + 对着真实图标集校验
├── classifier.test.ts  # 信号提取、权重、阈值
├── ai.test.ts          # 请求构造、响应解析、四种失败回退
└── e2e-vault.test.ts   # 真实目录落盘往返
```

`iconset.test.ts` 直接读**真实生成**的 `iconpark.json`，不是 fixture。因为这个插件的承诺就是「整套图标随包发布」，那么「每个默认类别都能解析」就是对**发布产物**的断言，必须对着它测。

`e2e-vault.test.ts` 断言写入后 frontmatter 逐字节不变、图标在正文首行、无哨兵色残留、清空后逐字节还原、二次扫描无操作。
