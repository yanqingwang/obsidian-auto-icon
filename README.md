# Auto Icon

根据笔记内容，自动给它配一个图标。32 个内置类别，本地规则引擎默认离线可用，AI 分类可选。

写入 frontmatter 的 `icon` 字段——对笔记内容零侵入，Obsidian 的文件属性面板能直接看到，其他插件也能读。

---

## 一句话激活

安装启用后，插件会提示一句：

> **Auto Icon 已就绪 —— 运行命令「为当前笔记分配图标」，或在设置里点「扫描整个 vault」即可开始。**

然后就结束了。剩下的由你决定：先试一个文件夹，还是直接扫全库。

---

## 设计：本地规则优先，AI 是加分项

**默认完全不调用 AI。** 分类靠本地规则引擎，零依赖、零成本、离线可用、秒级响应。这是「独立插件」这条路的底气——不需要挂到 vault-agent 下面，不需要任何密钥。

**AI 是可选增强。** 开启后每次分类请求一次你配置的接口（任何 OpenAI 兼容端点都行）。关键在于**任何失败都自动回退到本地规则**：key 错了、限流了、模型返回了一段散文、网断了——都回退，不中断扫描，还会提示一句原因。

这条 `NoteClassifier` 接口就是那个接缝：现在接规则引擎，将来换 AI 实现，管道一行都不用改。

## 32 个类别

上限是硬性的，在 `assertCategoryLimit` 里强制，不靠约定——所以从设置里加类别也不可能超过 32。

| | | | |
|---|---|---|---|
| 收件箱 | 项目 | 任务 | 决策 |
| 会议 | 报告 | 研究 | 资料 |
| 需求 | 设计 | 开发 | 缺陷 |
| 测试 | 部署 | 运维 | 文档 |
| 流程 | 规范 | 模板 | 归档 |
| 财务 | 合同 | 客户 | 供应商 |
| 招聘 | 面试 | 培训 | 战略 |
| 风险 | 想法 | 敏感 | 收藏 |

每个类别都能改名、换图标、改关键词、删除，也能自己加新的。

### 显式声明优先

frontmatter 里写 `type:` / `category:` / `kind:` 可以直接指定，权重 100，压过一切推断：

```yaml
---
type: bug
---
```

放在 `深度/` 目录里但声明了 `type: bug`，就归缺陷。

## 匹配是怎么算分的

七路信号加权求和，**每路每类别最多算一次命中**——否则一篇长文里顺带提到 `bug issue error defect 故障 异常`，就能靠篇幅压过一条用户明确写的 `#task` 标签。

| 信号 | 权重 | 说明 |
|---|---|---|
| frontmatter 声明 | 100 | `type` / `category` / `kind` |
| 标签精确命中 | 10 | `#task`、`#任务` 直接命中 |
| 文件夹 | 6 | `contract/` 命中合同 |
| 标签关键词 | 5 | `bug-report` 命中缺陷 |
| 文件名 | 4 | `2026-budget.md` 命中财务 |
| 小标题 | 3 | `上线检查清单` 命中部署 |
| 正文 | 1 | 只用来打破平局 |

**默认最低分 4。** 这个数字卡在文件夹(6)和文件名(4)之下、正文(1)之上，所以：用户明确写的标签、或名字对得上的文件夹，会被配图标；正文里偶然出现一个词，不会。这就是「有用的自动图标」和「每篇笔记都挂个随机符号」之间的分界线。

中文没有词边界，所以关键词是**子串匹配**——`本周周报汇总` 能命中 `report` 的 `周报` 关键词。

每个判定都会给出理由（`标签 #task`、`文件夹 工作/contract ~ contract`），预览窗口里直接显示。「为什么它觉得这篇是会议？」这种问题，看一眼就能回答，不用去读源码。

## 图标来源：可扩展，许可随源走

图标引用就是 `"来源:key"` 字符串，比如 `lucide:folder-kanban`、`emoji:📁`、`mine:chart`。

**内置两个来源：**

- **`lucide`** —— Obsidian 自带的 Lucide 图标集，ISC 许可，随 Obsidian 一起分发。无需打包任何素材。
- **`emoji`** —— Unicode 字符，无许可问题，到处都能显示。

**加自己的来源**：一个来源 = 一组图标 + 一个 id + 一个许可声明。许可必填，因为它提醒你这些图标的授权来自哪里；填了之后永远不会丢。

内置来源和用户来源走**完全相同的解析路径**，用户来源不是二等公民。

### 为什么每个图标都有回退值

每个类别都存两个引用：主图标 + 回退图标。运行时会检查主图标在这个 Obsidian 版本里存不存在，不存在就用回退。

这不是装饰。Lucide 会改图标名——`check-square` 改成 `square-check`、`building-2` 改成 `building`、`file-signature` 改成 `file-pen`——而 Obsidian 只分发它自己那版认识的名字。只钉一个名字，就意味着在别人机器上会**静默失效**。

所有 32 个 Lucide 名字都对当前的 lucide-static（1877 个图标）验证过。

## 安全

- **预览**：写入前弹窗，逐文件列出图标 + 判定依据，确认后才写
- **不覆盖**：默认只给没有图标的笔记配，手动设过的图标不会被自动覆盖。想强制覆盖用「重新扫描并覆盖已有图标」命令
- **不乱删**：分类失败的笔记**不会被清空图标**，只是不写。匹配不上和该删是两回事
- **范围可控**：设置里指定文件夹，留空 = 整个 vault，同一条代码路径

## 命令

| 命令 | 作用 |
|---|---|
| 为当前笔记分配图标 | 单篇 |
| 扫描整个 vault 并分配图标 | 全库（按设置的文件夹范围） |
| 扫描当前文件夹并分配图标 | 当前笔记所在文件夹 |
| 重新扫描并覆盖已有图标 | 强制覆盖已有图标 |
| 手动为当前笔记设置图标 | 从 32 个类别 + 所有用户来源里挑 |
| 清除当前笔记的图标 | 移除 frontmatter 的 `icon` |

功能区图标 = 「为当前笔记分配图标」。

## 安装

```bash
cd code/obsidian-auto-icon
npm install
npm run build
```

产物 `main.js` + `manifest.json` + `styles.css`。部署到 vault：

```bash
OUTDIR="/path/to/your/vault/.obsidian/plugins/auto-icon" npm run build
```

或手动复制这三个文件到 `<vault>/.obsidian/plugins/auto-icon/`。

### 代码结构

| 文件 | 职责 |
|---|---|
| `src/categories.ts` | 32 个默认类别、关键词、32 上限强制 |
| `src/sources.ts` | 图标来源解析、回退、用户来源 |
| `src/classifier.ts` | 信号提取 + 本地规则打分（纯函数） |
| `src/ai.ts` | 可选 AI 分类器，实现同一个接口 |
| `src/planner.ts` | 生成可预览的改动计划 |
| `src/settings.ts` | 设置、默认值、AI 配置 |
| `src/previewModal.ts` | 预览确认 |
| `src/SettingsTab.ts` | 设置界面 |
| `src/main.ts` | 命令与扫描流程 |

分类逻辑全是不依赖 Obsidian 的纯函数，所以打分行为可以脱离 vault 单测——风险本来就在这里。

### 测试

```
tests/
├── categories.test.ts    # 32 个类别、32 上限、克隆独立性
├── classifier.test.ts    # 信号提取、各项权重、阈值行为
├── sources.test.ts       # 引用解析、回退、用户来源
├── ai.test.ts            # 请求构造、响应解析、四种失败回退
├── planner.test.ts       # 分配/覆盖/跳过策略
└── e2e-vault.test.ts     # 真实目录：中文路径、混合 frontmatter、精确命中集合
```

`e2e-vault.test.ts` 断言的是**精确的命中集合**，不是比例——比例断言在这里没有意义（fixture 是 10 篇里 8 篇有标签，配 8 个图标才是对的），真正要保证的是「碰到的正好是该碰的那些，以及两篇无信号的笔记确实没被碰」。

`npm run smoke` 会真的 require 打包后的 `main.js`，检查 6 个命令、设置页、图标都注册成功，并核对默认类别确实是 32 个、AI 确实是关的。一个在 import 时就抛异常的插件，`tsc` 和 jest 都发现不了。
